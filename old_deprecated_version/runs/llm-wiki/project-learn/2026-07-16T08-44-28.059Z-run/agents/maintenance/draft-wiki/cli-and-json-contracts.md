# CLI and JSON interfaces

The `myelin` CLI is the public operator and detached-integration boundary: it registers commands in `src/commands/register.ts`, accepts command-specific validated arguments, and returns either concise text or an explicitly requested JSON result.

## Authority and response rules

`src/cli.ts` resolves the launch context, registers the ten command families, and prints the registry result. The small registry in `src/commands/registry.ts` selects the longest matching command path, returns exit `1` for unknown commands or handler validation failures, and renders `--help` from the actual registrations. `tests/commands/register.test.ts` verifies the central registration set and that every registrar receives the same immutable launch context.

Human output is the default. JSON is opt-in and command-specific; consumers must not parse human text. Most JSON commands serialize their service result (some use stable key ordering), including failure payloads where the command's service reports a failed outcome. Argument parsers reject unknown flags, missing values, unexpected positionals, invalid enum values, and invalid numeric bounds before calling their services. `--json` makes `project learn` suppress progress output, preserving one JSON value on stdout; its normal progress belongs on stderr.

The command line is also the intentional detached boundary. Core query code is in `src/query/`, but a detached MCP implementation must call `myelin memory query <key> <question> --json` rather than import root source (`README.md`, `src/commands/memory.ts`). Compatibility retains `LLM_WIKI_*` environment variables and `mcp__llm-wiki__*` tool names; they are external compatibility contracts, not current Myelin product names.

## Registered surface

The following is the complete currently registered surface from `src/commands/*.ts`; a slash separates sibling commands with the same authority boundary.

Bootstrap writes project state/shell and refuses a repository already owned by another key. |

Indexing calls the configured embedding provider and writes derived state. Lifecycle commands are preview-first: migration activates only after complete staged coverage and smoke check; rollback swaps healthy contracts; prune with apply deletes only retired/failed derived rows/tables and query cache, never canonical memory. | Installation and capture | `install [--provider codex] [--command-only] [--rebind] [--rollback] [--prune] [--bin-dir <absolute-path>] [--apply]`, `uninstall [--provider codex] [--apply]`, and `capture codex-hook`. | Install/uninstall preview by default. Every command accepts only the flags described by its parser. Positive-count flags reject zero and non-integers; embedding and ingest batch size are bounded at `1..500`. The `project reset` double confirmation is the strongest destructive guard in this surface. Installation/uninstallation and embedding lifecycle consistently use `--apply` as the write approval gate.

## Query JSON contract

`memory query --json` returns the `QueryResponse` shape defined in `src/query/memory-query-contracts.ts`: `answer`, `confidence`, `memory_scope`, `citations`, `candidate_ids`, `degraded`, `degraded_reason`, `source_tools`, `matches`, and `project_memory_matches`; `--debug` additionally exposes per-layer diagnostics (`layers`) including index counts, cache information, normalized question, and degradation state.

`--layer session` is the default and returns Session Memory matches; `--layer project` returns Project Memory section matches in `project_memory_matches` and leaves `matches` empty. Branch filtering is passed to retrieval; `current` resolves the registered repository branch. A degraded query returns nonzero human output, but its JSON response remains the machine-readable explanation. Confidence is deterministic evidence scoring, not a probability derived from embedding distance. `tests/commands/memory.test.ts` and `tests/query/memory-query-service.test.ts` cover session JSON/diagnostics, cache reuse, branch filtering, Project Memory result separation, degraded responses, and that confidence does not vary merely with vector distance.

This is a compatibility-safe integration contract: callers should use the response fields and citations, tolerate `degraded: true` with a nullable reason, and not depend on the human `answer` presentation or on internal SQLite tables.

## Documentation drift and known gaps

`docs/CLI.md` is the intended canonical reference, but it is incomplete relative to the live registry: it omits `project list`, `project packet`, `project reset`, `memory index project`, `memory eval project`, and both maintenance worker routes. Its listed commands remain useful where aligned, but the registry and command parsers are authoritative until the reference is updated.

`README.md` calls Session Memory vector retrieval the current facade while the implementation and tests support the explicit `--layer project` route; that statement is stale/incomplete, not a restriction on the current CLI.

The supplied [repository-identity.json](../repository-identity.json) verifies the checkout identity used for this run. Command-level tests substantiate representative validation and JSON behavior, but this subject did not establish end-to-end provider execution, detached-worker concurrency, or every individual parser error branch.
