# Use answer-domain Project Memory documentation maps

Project Memory creation should organize its first trusted wiki around answer domains future agents need to query and act on, rather than the old six-role page taxonomy. The six-role model produced plausible page titles without useful documentation, while answer domains let validation check whether rendered markdown covers product model, storage/retrieval, command workflows, curation/apply lifecycle, evidence/provenance, and current work/decisions.

Considered options: keep the six stable role pages with stricter sections, or let the curator design an unconstrained wiki map with answerability gates. We choose answer domains because they preserve deterministic validation while aligning the documentation shape with how agents will query Project Memory.
